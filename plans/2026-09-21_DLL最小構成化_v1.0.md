# DLL最小構成化

## ユーザー指示（原文・2026-09-21）
- 「DLLも最小限の構成にして」
  - 「CIのMinGW化」の作業中に受信。直前に提示した削減案（FileDialog のネイティブ化、`qgif`・`qico` の除外）の実施と、それ以外の不要ファイルの整理を含むと解釈する。

## 背景（実測済みの事実）
- v4.0.0 の公開 ZIP（MSVC 版）: 163 ファイル、展開 47.7MB、ZIP 18.8MB。Qt の DLL 18 個のうち、起動時に必須なのは 11 個。残りは QML の import で実行時に読み込まれる。
- 現在の CI パッケージ（MSVC 版）: 165 ファイル。Svg と qtiff は除外済み。
- `QtQuick.Dialogs` は `FileDialog`（開く・保存の 2 箇所）のためだけに使われ、DLL 3 個（約 2.9MB）と QML 22 ファイルを引き連れる。
- Qt 本体（Core、Gui、Quick、Qml など）は約 6 割を占め、動的リンクの Qt Quick を使う限り減らせない。

## 方針
- 不要な物を「実際に使われているか」で判定して外す。推測で外さない。外した状態でテストと起動確認を行う。
- 対象: `QtQuick.Dialogs`（ネイティブのファイルダイアログへ置換）、`qgif`・`qico`（読み込みは WIC のため不要）、QML モジュールのツール用メタデータ（実行に不要なもの）、ZIP 内の冗長なアイコンファイル。
- 検査: `verify_package.ps1` に「入れてはいけないファイル」を追加し、ファイル数とサイズを出力する。

## 実施内容
- `QtQuick.Dialogs` を廃止。`src/app/native_file_dialog.{h,cpp}`（Windows 標準の `IFileOpenDialog`/`IFileSaveDialog`）に置換し、`Main.qml` の `FileDialog` 2 つを削除。コントローラーに `showOpenImageDialog()` / `showSaveImageDialog()` を追加。保存形式の一覧（PNG・JPEG・BMP・TIFF・WebP・HEIC/HEIF）は `saveFileTypes()` に集約。
- `deploy.py`: `qgif`・`qico` プラグインを除外。QML の `*.qmltypes`（qmllint・Qt Creator 用メタデータ）を削除。`dist/` へのアイコンのコピーを廃止。`Qt6QuickDialogs2*` と `qml/QtQuick/Dialogs` を、万一残った場合の掃除対象に追加。
- `package.ps1`: ZIP へ `QuickImageView-icon.ico` を入れない（アイコンは exe に埋め込み済み）。
- `verify_package.ps1`: 入れてはいけないファイルに、`qgif`・`qico`・アイコン・`Qt6QuickDialogs2*.dll`・`qml\QtQuick\Dialogs`・`*.qmltypes` を追加。ファイル数と容量（MB）を出力。
- 新規テスト: 保存ダイアログが提示する全形式（png/jpg/jpeg/bmp/tif/tiff/webp/heic/heif）を `ImageEngine::save` が実際に書けること。TIFF のように「一覧に載せたが書けない」形式が再発しないための回帰テスト（HEIC/HEIF は HEIF エンコーダーが無い PC ではスキップ）。

## 確認項目と結果（ローカル・MinGW ビルド）
- 配布物（`dist/`）: 153 ファイル・54.4MB → 113 ファイル・49.7MB（−40 ファイル・−4.7MB）。Qt6 DLL 18 → 15、`imageformats` 4 → 2（`qjpeg`・`qwebp` のみ）、QML 125 → 91 ファイル、`*.qmltypes` 14 → 0、アイコン 1 → 0。
- CTest 2/2 成功。`verify_package.ps1` 成功。実機で本体を 6 秒起動し、応答あり・`crash.log` の増加 0。
- ネイティブのファイルダイアログ: 検査用の小さなプログラムで、開く・保存とも実際にダイアログが表示され（タイトルを確認）、自動で閉じるとキャンセル扱いで空を返すことを確認。ダイアログ内の操作（ファイル選択、形式の切り替え、拡張子の付与）は未確認。
- 残る Qt6 DLL 15 個は、起動時に必須の 11 個と、Basic スタイル（3 個）・Layouts（1 個）。いずれも UI が実際に使うため外せない。
- 残置: MSVC 版 Qt 向けの VC++ ランタイム同梱処理（`deploy.py`）と検査の分岐。公式のリリース経路（MinGW）では使わないが、MSVC 版 Qt でビルドした場合に壊れた ZIP を出さないための保険として残している。

## 結果（CI と ZIP の実測）
| | v4.0.0（MSVC、公開済み） | 現在（MinGW、CI と一致） |
|---|---|---|
| ファイル数 | 163 | 123（うち文書 10 ファイル） |
| 展開サイズ | 47.7MB | 49.7MB |
| ZIP | 18.8MB | 19.4MB |
| Qt6 DLL | 18 個（約 31MB） | 15 個（約 43MB） |

- 減らしたもの: ファイルが 40 個減った（Svg、TIFF・GIF・ICO プラグイン、QtQuick.Dialogs 一式、QML の `*.qmltypes`、ZIP 内のアイコン）。
- サイズが増えた理由: MinGW 版の Qt DLL は MSVC 版より大きい（Qt6Core は約 9.8MB → 10.6MB、Qt 全体で約 31MB → 約 43MB）。MinGW のランタイム DLL 3 個（2.3MB）も加わる。不要物の削減（約 4.7MB）を、この差が上回った。
- ストリップは無効: Qt の DLL は既にストリップ済みで、`strip --strip-unneeded` でも 43.1MB → 43.0MB（0.2MB）にしかならない（コピーで測定、配布物は変更していない）。
- 残るのは Qt Quick の本体と、UI が使う Controls（Basic）・Layouts で、これ以上は UI の作り直し（Widgets 化）か Qt の静的ビルドが必要。
