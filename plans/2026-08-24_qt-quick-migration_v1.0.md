# QuickImageView v3.1.2 Qt Quick移行 実装計画書

## 1. 目的

QuickImageView v3.1.2を、Quickシリーズ共通仕様と`quick-app-template`に準拠したQt Quick/QMLアプリとして実装する。製品バージョンは`v3.1.2`、技術基準年は`2026年`とする。

現行Win32版の画像表示・編集・保存・EXIF・クリップボード・ヘルプ・バージョン情報を維持しながら、UIをQMLへ移行し、共通のダークテーマ、日英切替、画面構成、配布文書、ビルド手順を一貫させる。

## 2. 準拠事項

- `01_フォルダ構成.md`に従い、ソース、リソース、アセット、文書、計画、ビルド、配布物を分離する。
- `11_アプリ仕様.md`に従い、ダークテーマ、メニューバー、右上の言語切替、ヘルプ、中央モーダルのバージョン情報を実装する。
- 英語をベース名、日本語を`_jp`接尾辞とする日英ペアを維持し、各文書の冒頭に相互リンクを置く。
- UI、実行ファイルメタデータ、マニフェスト、CLI出力、README、配布文書、変更履歴のバージョンを`3.1.2`へ統一する。
- `assets/maktak105-V04-01.jpg`をAbout画面の作者ワッペンに使用する。
- 配布方式は現行どおり、GitHub Releasesで署名なしのZIPを配布する。有料コード署名証明書やMSIXは採用しない。

なお、2026年版という位置付けはUI技術、設計分離、自動テスト、CI、依存関係管理、アクセシビリティ、高DPI対応などの技術水準を示すものであり、配布方式や署名方式を変更することを意味しない。
- CIでC++テスト、QMLテスト、静的解析を自動実行する。
- クラッシュログ、アクセシビリティ、キーボード操作を実装・検証対象とする。

## 3. 現状と維持する資産

- UI、画像処理、EXIF、クリップボード、ヘルプ、About、メニューが`core/native/main.cpp`に集約されている。
- 画像読込・変換はWindows Imaging Component（WIC）を使用している。
- WebPは同梱の`third_party/libwebp/`を静的リンクしており、WebP機能は外部環境依存にしない。
- EXE、MSI、ファイル関連付け、ヘルプ埋め込み、Windows用アイコンはWindows固有処理に依存している。
- 現行Win32版は`main`ブランチで維持し、Qt Quick版は`codex/qt-quick-migration`で作業する。

## 5. 実装方針

### 5.1 UI

- Qt 6、Qt Quick、Qt Quick Controls 2、Qt翻訳機構を使用する。
- QMLでタイトルバー、暗色メニューバー、左サイドパネル、メイン表示、ステータスバー、ヘルプ、Aboutを構成する。
- ダーク背景、濃色パネル、シアン〜青のアクセント、角丸、境界線、状態色を共通UIトークンとして管理する。
- 右上に地球アイコン付きの日本語 / English切替ピルボタンを配置する。
- `resources/help/help.md`と`help_jp.md`をビルド時に埋め込み、QML側で見出し・段落・箇条書きを読みやすく表示する。
- Aboutは中央モーダルの暗色カード、シアン境界、`Ver. 3.1.2`、開発環境、制作者、作者ワッペン、OKボタンを表示する。

### 5.2 C++とlibwebp

- GUI非依存の画像処理を`core/native/`へ分離する。
- WICによる画像読込、リサイズ、回転、反転、切り抜き、色変換を維持する。
- `third_party/libwebp/`の同梱ライブラリを静的リンクし、WebP読込・保存を環境依存なしで提供する。
- EXIF、クリップボード、Undo/Redo、原本保護、既存出力ファイル保護をC++層で管理する。
- QML公開型は画像状態、編集コマンド、通知、設定、言語状態に分離する。
- 大画像の処理は必要に応じてワーカースレッドへ移し、進捗・完了・失敗・キャンセルを通知する。

### 5.3 自動テストしやすい設計

- 画像処理、ファイル保護、EXIF、WebP、クリップボードをQML・Win32 APIから分離し、C++のGUI非依存ユニットテストで検証できるようにする。
- QMLの主要部品と操作対象には固定した`objectName`または`Accessible.name`を付け、表示文言や座標に依存しないUIテストにする。
- UI状態を「未読込・読込中・表示中・編集中・保存中・完了・失敗」に明示的に分け、状態遷移をテストから観測できるようにする。
- ファイル選択、クリップボード、保存先、確認ダイアログ、時間のかかる処理はインターフェース化し、テスト用Fake/Mockへ差し替えられるようにする。
- テスト実行時だけ有効な起動オプションまたはテストフックを用意し、実ユーザーデータや対話型ダイアログに依存しないようにする。
- テスト用画像・EXIF・WebPサンプルは固定fixtureとして管理し、出力画像のピクセル、形式、メタデータ、原本のハッシュを検証する。
- UIテストは日本語・英語、高DPI、リサイズ、ヘルプ、About、キーボード操作を対象にし、スクリーンショット比較は補助検証として使用する。
- UIテストと並列実行できるよう、作業用ディレクトリ、設定、クリップボードをテストケースごとに分離する。

### 5.3 Windows固有処理

- Win32 APIはファイル関連付け、Explorer右クリック登録、ファイル属性、MSI、EXEリソースなどに限定する。
- 画面レイアウト、ボタン、メニュー、ヘルプ、About、ファイル選択はQt/QMLで実装する。
- Qtランタイムと必要なプラグインを配布物へ収集し、Qtの別途インストールを要求しない。
- 配布は現行どおり署名なしZIPを基本とし、署名なしMSIやMSIXを正式配布方式へ追加しない。

## 6. 実装手順

1. `document/spec.md` / `spec_jp.md`へv3.1.2の画面・機能・互換条件を整理する。
2. Qt 6、CMake、MinGW-w64またはMSVC、Qtデプロイ環境を確認する。
3. テンプレート準拠の`resources/`、`assets/`、`document/`、`dist/`、`build-tools/`、`third_party/libwebp/`を確認する。
4. 現行Win32版を変更せず、Qt Quickの最小起動ターゲットを追加する。
5. C++エンジンと同梱libwebpのリンクを分離し、既存テストを移植・追加する。
6. QMLのメイン画面、画像表示、ズーム、パン、ファイルオープンを実装する。
7. 編集、Undo/Redo、クリップボード、EXIF、保存、原本保護をQt UIへ接続する。
8. 固定ID、アクセシビリティ名、状態モデル、Fake入替点、テストfixtureを追加する。
9. QuickシリーズUI、日英切替、ヘルプ、About、作者ワッペンを実装する。
10. `build-tools/`のビルド、ヘルプ埋め込み、Qtデプロイ、ZIP/MSI生成を更新する。ルートの`build.bat`は入口だけにする。
11. README、変更履歴、技術文書、配布文書、ライセンス・第三者ソフトウェア表記をv3.1.2へ更新する。
12. CIでクリーンビルド、C++テスト、QML UIテスト、静的解析を自動実行する。
13. クラッシュログ、アクセシビリティ、キーボード操作、起動スモークテスト、日英UI目視、配布物検査を実施する。
14. `plans/2026-08-24_qt-quick-migration_結果_v1.0.md`へ実施結果を記録する。

## 7. 検証基準

- CMakeのクリーンビルドが成功し、中間生成物が`build/`に生成される。
- C++テスト、画像読込・編集・保存、Undo/Redo、クリップボード、EXIFが通る。
- C++のGUI非依存テストだけで画像処理、WebP、EXIF、原本保護、既存出力保護を再現性よく検証できる。
- QML UIテストが固定ID・状態・Fake入替点を使って自動実行でき、座標・表示言語・実ユーザー環境に過度に依存しない。
- UIテストでファイルオープン、編集、Undo/Redo、保存、言語切替、ヘルプ、About、OK終了を一連で検証できる。
- テストは一時ディレクトリとfixtureを使用し、実ユーザーファイル、設定、クリップボードを破壊しない。
- テスト失敗時に終了コード、ログ、スクリーンショット、対象テスト名を取得できる。
- CIでC++テスト、QMLテスト、静的解析が毎回実行され、失敗時にログと成果物を確認できる。
- 未処理例外や致命的エラー時に、アプリ固有のクラッシュログまたはミニダンプを保存できる。ログには個人情報や画像内容を記録しない。
- スクリーンリーダーで主要操作の名前・役割・状態を取得でき、色だけに依存しない。
- Tab移動、Shift+Tab、Enter、Space、Esc、メニューショートカット、ヘルプ・Aboutの閉じる操作をキーボードだけで完了できる。
- 原本画像と既存出力ファイルを変更しない。
- 同梱`third_party/libwebp/`でWebP読込・保存が動作し、外部libwebpの有無に左右されない。
- WIC依存の形式は、実行環境で利用できる形式として文書化する。
- 日英切替がメニュー、ステータス、ヘルプ、Aboutへ反映される。
- 標準Windowsの白いボタンや明るいダイアログが残っていない。
- 右上の地球アイコン付き言語切替、暗色パネル、角丸部品、シアンアクセントを確認する。
- Aboutが中央モーダルで表示され、背面が暗転し、`Ver. 3.1.2`、開発環境、制作者、作者ワッペン、OKボタンが表示される。
- 高DPI、リサイズ、長文ヘルプ、画像拡大表示でレイアウトが破綻しない。
- 日英UIの実画面スクリーンショットを`assets/`へ保存し、目視確認する。
- `dist/binary/`にはバイナリ、`dist/documents/`には日英のreadme・history・LICENSEが正しく入る。
- GitHub Releases用ZIPを展開して起動でき、SHA-256とREADME・配布文書の記載が一致する。
- 配布物に署名や証明書を要求せず、署名なし配布であることを文書化する。
- `git diff --check`、秘密情報・不要ファイル検査、Git管理対象検査が通る。

## 8. リスクと対策

| リスク | 対策 |
| --- | --- |
| Qtランタイム・プラグインの配布漏れ | Qtデプロイ処理と配布物検査をビルドへ組み込む |
| QMLとC++の状態不整合 | ViewModelを状態源とし、変更通知とテストを明示する |
| UIテストが座標や文言変更で壊れる | 固定ID、アクセシビリティ名、状態モデル、テスト用Fakeを使用する |
| テストが実環境のファイルやクリップボードを壊す | fixtureとケースごとの一時領域を使用し、実データをテスト対象にしない |
| 大画像でUIが停止する | ワーカースレッド、進捗、キャンセルを実装する |
| WICとQt画像形式の差異 | 読込・保存の正本をC++/WIC/libwebp層に限定する |
| QuickシリーズUIからの逸脱 | `11_アプリ仕様.md`の項目ごとに実画面を検査する |
| 日英文書の不一致 | 英語版と`_jp`版を同時更新し、相互リンクを確認する |
| 移行途中で現行版が壊れる | Qt版を別ターゲット・別出力で構築し、Win32版を維持する |

## 9. 対象外

- Qt Quick版完成前に現行Win32版を削除すること。
- 移行を理由に対応形式、コーデック、原本保護、既存出力保護の仕様を変更すること。
- 移行と同時に新しい画像編集機能を追加すること。
- 配布方式、ライセンス、第三者ソフトウェア表記を独断で変更すること。特にMSIXや有料署名を追加しない。

## 10. 完了条件

Qt Quick版が検証基準を満たし、ソース、ビルドスクリプト、同梱libwebp、ヘルプ、日英ドキュメント、バージョン情報、配布物、CI、インストーラーの全てがv3.1.2の実体と一致した時点で完了とする。

完了までは`codex/qt-quick-migration`で作業し、実施結果を記録したうえで、レビュー後に`main`へ統合する。
