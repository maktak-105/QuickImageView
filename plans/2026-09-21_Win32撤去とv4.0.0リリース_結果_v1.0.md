## 確認した事実と懸念
- ローカル Qt（MinGW 6.10.3）の `QImageWriter` は PNG・JPEG・BMP・WebP を書き込めるが、TIFF・GIF・HEIC は「Unsupported image format」（Qt の TIFF プラグイン `qtiff` が無い）。アプリは HEIC/HEIF のみ WIC へフォールバックする。CI の Qt（MSVC）で TIFF プラグインが入るかは未確認。文書は「TIFF は Qt の TIFF プラグインが必要」と記載した。
- 第三者ライセンス: Qt（LGPL 3 系）の記載を追加したが、法務確認はしていない。

## GitHub Actions とリリース（2026-09-21）
- `main`（f3715b2）を push。CI: Qt インストール・構成・ビルド・テストは成功、静的解析だけ失敗。
  原因は CI 設定の不備（`choco install cppcheck` 後に PATH が反映されず「cppcheck が認識されない」）。qt ブランチの直近 3 回の CI も同じ失敗で、静的解析は一度も実行されていなかった。ローカルの Cppcheck 2.20 では指摘なし。
- 修正（abb54a5）: `ci.yml` で Cppcheck のインストール先を `GITHUB_PATH` へ追加。CI は全工程成功。
- タグ `v4.0.0`（annotated、abb54a5）を push。Release ワークフロー成功。
- 公開物: `QuickImageViewQt-v4.0.0-win64.zip`（19,708,077 バイト）と `SHA256SUMS.txt`。ダウンロードして SHA-256 が一致（E11027A7…5440）することを確認。ZIP に exe・Qt6Core.dll・platforms・imageformats・qml・readme・LICENSE・第三者ライセンス・libwebp 通知が入っていることを確認。
- 公開 ZIP の `imageformats` に `qtiff.dll` が含まれる（ローカル MinGW Qt には無い）。リリース版では TIFF 保存が使える見込みだが、実機での保存は未確認。
- `win32-legacy` は push していない。リモートのブランチは `main` と `qt`。
