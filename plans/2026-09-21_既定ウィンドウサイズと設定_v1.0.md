# 既定ウィンドウサイズと設定

## ユーザー指示（原文・2026-09-21）
- 「これくらいにしたい、＋設定から数値で指定できるようにして」
  - ユーザーがアプリのスクリーンショット（`QuickImageView 4.0.0`、日本語 UI、画像を表示中）を添付。直前の質問「これデフォルトのウィンドウサイズいくつ？」（回答: 1180×760 論理ピクセル）に続く指示。

## 前提
- 現在の既定サイズは `src/ui/Main.qml` の `width: 1180` / `height: 760`（クライアント領域、論理ピクセル）。最小サイズは 480×320。
- v4.1.0 として作り直す予定（ユーザー指示「v4.1.0で作り直す、その前にドキュメント類の更新」）。この機能は v4.1.0 に含める。文書更新とリリースは、この機能の後に行う。

## ユーザー追加指示（原文・2026-09-21、作業中に受信）
- 「720×480にしよう」→ 既定のウィンドウサイズを 720×480 にする（`Main.qml` の `width` / `height` と同じ、クライアント領域の論理ピクセル）。

## 添付スクリーンショットの実測
- 画像は 758×547 px（メタデータ 96dpi）。タイトルバーは暗色（#202020）で、ダークなタイトルバーが効いていることが分かる。
- QML のメニューバー（`implicitHeight: 32`）が画像上でも 32px（31〜62 行）なので、撮影は表示倍率 100% と判断できる。フレームは左右・上下とも 1px、タイトルバー 30px。よってクライアント領域は約 756×515。ユーザーはこれより小さい 720×480 を選んだ。

## 解釈
1. 既定のウィンドウサイズを、添付スクリーンショットの大きさ程度にする。
2. 設定ダイアログから、ウィンドウサイズを数値（幅・高さ）で指定できるようにする。

## 方針（実測後に確定）
- 既定値は 720×480（ユーザー指定）。
- 設定は `%LOCALAPPDATA%\maktak-105\QuickImageView\settings.ini`（既存の `crash.log` と同じ場所）へ保存。次回起動時の既定サイズとして使い、OK 時に現在のウィンドウにも即時適用する（最大化中は適用しない）。
- 範囲は最小 480×320（ウィンドウの最小サイズと同じ）から画面の作業領域まで。範囲外は丸める。

## 実施内容
- 既定のウィンドウサイズを 720×480（クライアント領域、論理ピクセル）にした。最小は 480×320 のまま。
- 設定ダイアログ（ファイル > 設定）に「ウィンドウ」の項を追加し、幅・高さを数値（SpinBox、直接入力可）で指定できるようにした。範囲は 480×320〜7680×4320。OK を押したときに値が変わっていれば、保存して現在のウィンドウにも反映する（最大化中は反映しない）。値が変わっていなければ、手で変えた現在の大きさを崩さない。
- 保存先は `%LOCALAPPDATA%\maktak-105\QuickImageView\settings.ini`（`[window]` の `width` / `height`）。起動時は、保存値をプライマリ画面の作業領域に収まるよう丸めて使う。範囲外・壊れた値は 480×320〜7680×4320 に丸める。
- コントローラー: `windowWidth` / `windowHeight` / `startupWindowWidth` / `startupWindowHeight` / 最小・最大のプロパティと `setWindowSize()`、`windowResizeRequested` シグナル、`setSettingsFile()`（テスト用）。
- 副作用の修正（既定サイズを小さくしたことで顕在化）: `HelpView`（760×620）と `AboutDialog`（380×510）が新しい既定ウィンドウより大きく、はみ出して切れる状態だった。5 つのダイアログ（ヘルプ、バージョン情報、設定、リサイズ、置換確認）を「ウィンドウより大きくならない・はみ出す分はスクロール」に変更。
- `deploy.py`: フォルダー削除にリトライを追加（`dist\qml\...` の削除が「別のプロセスが使用中」で止まる現象が 3 回再発したため）。

## 確認項目と結果
- コントローラーのテスト: 既定が 720×480、保存して次回起動で読み戻せる、範囲外・壊れた値が丸められる（計 3 件、ファイルは平文の ini で書き込みも確認）。全体 27 件成功、1 件スキップ（HEIF エンコーダー無し）。
- QML のテスト（新規 `tst_dialogfit.qml`、実コントローラーを使用）: ヘルプ・バージョン情報・置換確認・設定が、最小（480×320）・既定（720×480）・大きい窓（1400×900）で、ウィンドウ内に収まる。大きい窓では従来の大きさ（380×510、760×620）を保つ。設定ダイアログに保存値（720/480）と範囲（480/320〜7680/4320）が出る。全 21 件成功。修正前の状態では、このテストが失敗する（テスト作成時に確認）。
- 実機（自動操作、UI 操作なし。配備済み `dist` の exe）: 設定なしで 720×480（125% 表示の画面で 900×600 px）。900×600 を保存すると 900×600 で起動。10×10 は 480×320、99999×99999 は画面の作業領域（1536×816）、壊れた値は 480×320。`crash.log` の増加 0、検査用の `settings.ini` は削除済み。
- cppcheck: 指摘なし。パッケージ検査: 成功（123 ファイル・49.7MB、ZIP 19.4MB）。
