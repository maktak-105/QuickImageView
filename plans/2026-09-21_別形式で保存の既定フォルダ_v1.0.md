# 別形式で保存の既定フォルダ

## ユーザー指示（原文・2026-09-21）
- 「別形式で保存、デフォルトは元画像のあったところのフォルダにすること」

## 前提（確認済みの事実）
- 3.x（Win32 v3.1.3）の保存ダイアログは初期フォルダーを指定せず（`lpstrInitialDir` 未設定）、Windows が覚えている最後のフォルダーで開いていた。今回の要望は 3.x の復元ではなく、新しい挙動。
- Qt 版の現状: `NativeFileDialog::pickSaveFile()` は初期フォルダーを指定せず、同じく Windows 任せ。

## 解釈
- 「別形式で保存」のファイルダイアログを、現在表示している画像が置かれているフォルダーで開く。
- 別形式で保存すると保存先が「現在の画像」として読み込み直される（既存仕様）ので、その後の「別形式で保存」は、保存先ファイルのあるフォルダーで開く（現在の画像のフォルダー）。
- 画像のファイルがない場合（例: 貼り付けのみ）や、フォルダーが存在しない場合は、Windows の既定に任せる。
- ファイル名の既定は変えない（要望に無いため）。

## 方針
- `IFileDialog::SetFolder` で毎回そのフォルダーから開く（`SetDefaultFolder` は Windows が覚えている前回のフォルダーに負けるため使わない）。
- フォルダー決定のロジックは単体テストで固定し、実際のダイアログが指定フォルダーで開くことは、ダイアログを自動で操作する検査プログラムで確認する。

## 実施内容
- `NativeFileDialog::pickSaveFile()` に `initialFolder` を追加し、`IFileDialog::SetFolder`（`SHCreateItemFromParsingName` で作った項目）で、毎回そのフォルダーから開く。
- コントローラー: `initialSaveFolder()`（現在の画像のファイルがあるフォルダー。ファイルがない・フォルダーが無い場合は空）を追加し、`showSaveImageDialog()` が渡す。ファイル名の既定は変えていない。

## 確認項目と結果（ローカル）
- コントローラーのテスト（新規）: 画像が無いと空、開くとその画像のフォルダー、別フォルダーへ保存して読み込み直すと保存先のフォルダー、画像を閉じると空。全 31 件成功（スキップ 0）。QML 28 件成功。
- cppcheck: 指摘なし。

## 未確認
- 実際の「別形式で保存」ダイアログが、そのフォルダーで開くこと（コードは Windows の `SetFolder` を呼ぶだけで、ダイアログ内の表示は UI 操作が要るため未確認）。自動でダイアログを操作する検査（保存ボタンを押して、返るパスのフォルダーを確認する）は、次のセッションで行う。
- 保存後にフォルダーが変わる挙動（保存先が現在の画像になるため、次回の既定は保存先のフォルダー）は、解釈に基づく。意図と違えば指示を受けて直す。
