# 配布物のDLL数調査

## ユーザー質問（原文・2026-09-21）
- 「まぁいいわ、あとQtのDLL、こんなにたくさん配布しないといかんの？」
  - 直前の「-binary をつけるルールだったか」への回答（テンプレート規定・他アプリも同じ）を受けて、質問は了承済み（「まぁいいわ」）。

## 前提
- 配布物は CI（MSVC / Qt 6.10.3）が作る ZIP。ローカルの MinGW ビルド（`dist/`）とは DLL の構成が異なる可能性がある。
- ユーザーの指示は質問であり、変更の指示はまだない。実測して回答し、削減案を提示する。

## 調査結果（v4.0.0 の公開 ZIP を実際にダウンロードして計測）
- 規模: 163 ファイル、展開 47.7MB、ZIP 18.8MB。
- 内訳: Qt の DLL 18 個（約 31MB）＋ exe 1 個 ＋ imageformats 6 個（1.6MB）＋ platforms 1 個（1.0MB）＋ `qml/` 内の QML モジュール 125 ファイル（1.9MB）＋ 文書。
- 大きいのは Qt6Core 9.8MB、Qt6Gui 9.1MB、Qt6Quick 6.2MB、Qt6Qml 5.1MB の 4 個で 30MB（全体の 63%）。これらは Qt Quick アプリの本体で外せない。
- 起動時に静的に必要な DLL（exe からの import の閉包）は 11 個: Qt6Core, Gui, Network, OpenGL, Qml, QmlMeta, QmlModels, QmlWorkerScript, Quick, QuickControls2, QuickTemplates2。
- QML の import で実行時に読み込まれる DLL は 7 個: QuickControls2Basic, QuickControls2BasicStyleImpl, QuickControls2Impl（Controls の Basic スタイル）、QuickLayouts、QuickDialogs2, QuickDialogs2QuickImpl, QuickDialogs2Utils（`FileDialog` 用）。
- 不要なのは `Qt6Svg.dll`（0.6MB）と `imageformats\qsvg.dll`: アプリは SVG を使っていない（コード・QML に参照なし）。windeployqt がプラグインごと同梱しているだけ。
- `QtQuick.Dialogs` は `FileDialog`（開く・保存の 2 箇所）のためだけに使っており、関連の DLL 3 個（計 2.9MB、うち QuickImpl が 2.7MB）と `qml\QtQuick\Dialogs` の 22 ファイルを引き連れる（合計約 3.2MB）。
- 【不具合】MSVC のランタイム DLL（MSVCP140、MSVCP140_1、MSVCP140_2、VCRUNTIME140、VCRUNTIME140_1）を ZIP に同梱していない。Qt の各 DLL がこれらを import している。`package.ps1` は同梱対象に含めているが、`deploy.py` が windeployqt に `--compiler-runtime` を渡していないため、CI の ZIP には入らない。Visual C++ 再頒布可能パッケージが未導入の PC では起動できない可能性が高い（UCRT の `api-ms-win-crt-*` は Windows 10/11 標準）。文書の動作環境にもこの要件は書いていない。ローカルの MinGW ビルドは libgcc/libstdc++/libwinpthread の 3 DLL を同梱するため自己完結している。
- 削減余地（見積もり）: SVG 除外で −0.6MB（2 ファイル）、FileDialog をネイティブ化して Dialogs 一式を除外で −3.2MB（25 ファイル）。合計で全体の約 8%。残りの 9 割超は Qt 本体で、動的リンクの Qt Quick を使う限り減らせない。

## 大きく減らす方法（今回は非推奨）
- Qt を静的ビルドして単一 exe にする: Qt をソースからビルドする必要があり（CI も含め大工事）、LGPL の再リンク要件（オブジェクトファイルの提供等）の検討が必要。
- Qt Quick から Qt Widgets へ書き換える: DLL 数は減るが UI の全面書き換え。
- UPX などの圧縮: ZIP が既に圧縮されるためダウンロード容量は減らず、誤検知のリスクが増える。

## ユーザー選択（原文・2026-09-21）
- 配布物の方針: 「不具合修正+SVG除外(推奨)」（MSVC ランタイム DLL を ZIP に同梱し、SVG を除外する。FileDialog のネイティブ化と CI の MinGW 化は行わない）。

## 実施内容
- `scripts/deploy.py`: `windeployqt` に `--no-svg` を渡し、プラグイン除外に `qsvg` を追加（`Qt6Svg` は不要 DLL の掃除対象にも追加）。MSVC ビルドの Qt を検出した場合（`libstdc++-6.dll` が無い場合）に、Visual Studio の再頒布ディレクトリ（`VCToolsRedistDir`、無ければ `vswhere` で最新の VS を探索）から `vcruntime140.dll`・`vcruntime140_1.dll`・`msvcp140.dll`・`msvcp140_1.dll`・`msvcp140_2.dll` を `dist/` へコピーする。見つからなければ失敗して止める（壊れた ZIP を出さない）。
- 新規 `scripts/verify_package.ps1`: パッケージの必須ファイル（C++ ランタイム DLL を含む。MinGW なら MinGW の 3 DLL、MSVC なら VC++ の 5 DLL）と、不要ファイル（`Qt6Svg.dll`、`imageformats\qsvg.dll`、旧名の `QuickImageViewQt.exe`）の不在を検査する。
- `ci.yml`: 毎回の push で「Qt ランタイム配置 → パッケージ作成 → 検査」を実行する（公開はしない）。`release.yml`: 直書きだった必須ファイル一覧を `verify_package.ps1` の呼び出しに置換。
- 文書: 配布手順・配布用 readme・第三者ライセンス（Microsoft Visual C++ ランタイムの項を追加）を更新。

## 検証（ローカル・MinGW ビルド）
- 探索ロジック: この PC の VS 2022 Build Tools の再頒布ディレクトリ（14.44.35112、`Microsoft.VC143.CRT`）から 5 個すべて見つかった。
- 分岐: MSVC 分岐（5 個コピー）、MinGW 分岐（何もしない）、VS 不在（メッセージを出して停止）の 3 通りを一時フォルダーで実行して確認。
- `build.py`: 成功、CTest 2/2。`dist/` に `Qt6Svg.dll` と `qsvg.dll` が無いことを確認。
- `verify_package.ps1`: 実パッケージで成功（exit 0）。ランタイム欠落＋`Qt6Svg.dll` 混入の不正パッケージでは失敗（exit 1、5 個の欠落と Svg を列挙）。
- オフスクリーン起動: 5 秒動作継続、`crash.log` の増加 0。
- 注意: ローカルは MinGW ビルドのため、MSVC の実際の ZIP（CI 生成物）はまだ検証していない。CI で確認する。

## 確認項目
- CI（MSVC / Qt 6.10.3）で「Qt ランタイム配置」と「Verify package」が通ること。結果は結果ファイルに追記する。
