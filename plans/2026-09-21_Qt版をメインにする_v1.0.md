# Qt版をメインにする

## ユーザー指示（原文・2026-09-21）
- 「QuickImageViewはQtをメインに」
- 確認への回答: 「main を qt の内容に置換」（main の履歴は残し、Qt版の内容を main に取り込む。Win32版は旧ブランチへ退避。push は別途確認）

## 調査結果（2026-09-21 時点・読み取りのみ）
- リモートの既定ブランチは `main`。ローカルは `qt` をチェックアウト中だった。
- `main` は Win32/C++ 実装（`src/app/main.cpp`）。v3.1.3 リリース済み、MSI 配布・テンプレート準拠構成に移行済み（2026-09-20 まで 6 コミット）。
- `qt` は Qt Quick 実装（`qml/`, `core/`）。`main` から 2026-08-24 に分岐し 7 コミット（〜2026-09-17）。
- `core/native` → `src/app` などのディレクトリ再編で乖離。`git merge-tree` で試算し、衝突 20 ファイル（うち 11 はディレクトリ移動の追随）と判明。

## 実施内容（ローカルのみ・push なし）
1. Win32版の退避: ローカルブランチ `win32-legacy` を `origin/main`（897dcfa）から作成。upstream は未設定（誤 push 防止）。
2. ローカル `main` を `origin/main` へ fast-forward（6 コミット遅れだった）。
3. `origin/qt` を `main` へ `--no-ff` でマージし、衝突を解消。
   - Qtソース: `core/native/qt_*`・`image_engine.*`・`quick_image_provider.*` → `src/app/`（git のリネーム検出に従う）。
   - パス追随: `CMakeLists.txt`、`qt_resource.rc`、`qt_app_controller.cpp`（qrc パス `:/src/app/help/`）、`tst_qt_app_controller.cpp`、`scripts/deploy_qt.py`（アイコン）、`scripts/install.ps1`（アイコン。main 側に旧パス残りがあった不具合を同時修正）。
   - ビルド入口: ルート `build.bat` は main 方針で廃止し、`qt` 引数の分岐を `scripts/build.bat` へ移植。`scripts/build_qt.py` の中間生成先を `build/intermediate/qt-mingw1310` へ。
   - バージョン: main のリリース済み 3.1.3 を採用（CMake・ヘルプ・テスト・AGENTS.md・配布文書）。
   - ヘルプ本文: Qt版の本文（`origin/qt`）を採用。
   - CI: Qt版の構成（Qt インストール、Qt/QML テスト、cppcheck）を採用。main で外された `-G "Visual Studio 17 2022"` 固定は付けない。
   - Release: Qt版の ZIP 配布を採用し、main の「既存タグ指定の手動実行」「SHA256SUMS.txt」を統合。ZIP 名はタグから生成。MSI は Win32 exe 専用のためリリースから外した。
   - AGENTS.md: 配置ルールと `main` の位置づけを更新。
