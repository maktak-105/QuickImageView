# CIのMinGW化

## ユーザー指示（原文・2026-09-21）
- 「MinGW にして」
  - 直前の質問「なんでＭＳＶＣ版でやらせてるの？」への回答（MSVC は qt ブランチから引き継いだだけで、意図した選択ではない。テンプレートと他の 6 アプリは MinGW）を受けての指示。

## 背景（確認済みの事実）
- CI（`ci.yml`）と Release（`release.yml`）は、MSVC 版の Qt（`win64_msvc2022_64`）と Visual Studio 2022 でビルドしている。qt ブランチ（d7bda67、2026-08-24）で導入され、理由の記録は無い。Win32 版 3.x の CI も MSVC だった。
- ローカルの開発ビルド（`scripts/build.py`）は MinGW 13.1.0 と MinGW 版 Qt 6.10.3。テンプレートの Actions のひな形と他の 6 アプリの `release.yml` は MinGW。
- 環境差で実際に起きたこと: 手元（MinGW）にだけ TIFF プラグインが無く TIFF 保存が失敗した。MSVC 版には VC++ ランタイム DLL が ZIP に入っていなかった。

## 方針
- CI と Release を MinGW 版 Qt 6.10.3 ＋ MinGW 13.1.0（`tools_mingw1310`）でビルドする。
- ビルド・テスト・Qt ランタイム配置は、手元と同じ `scripts/build.py` を使う（同じ経路にして環境差をなくす）。
- ZIP には MinGW のランタイム DLL（libgcc_s_seh-1、libstdc++-6、libwinpthread-1）が入る。`verify_package.ps1` の MinGW 分岐で検査する。
- 文書（環境・配布・配布用 readme・第三者ライセンス）の記述を、MSVC から MinGW に合わせて更新する。
- CI が通るまで Private リポジトリで繰り返し確認する。タグ・Release・公開状態は変更しない。

## 実施内容
- `ci.yml` / `release.yml`: Qt を `win64_mingw`、MinGW を `tools_mingw1310`（`qt.tools.win64_mingw1310` = MinGW 13.1.0）で導入（`jurplel/install-qt-action@v4`）。`aqt list-qt` / `aqt list-tool` で名前を確認済み。
- ビルド・テスト・Qt ランタイム配置は `python scripts/build.py`（手元と同じ）。`QT_ROOT` は `QT_ROOT_DIR`、`QT_MINGW_BIN` は `<Qt のルート>\Tools\mingw1310_64\bin`。Qt 付属の MinGW に `mingw32-make.exe` が含まれることを確認済み。
- テストログのアップロード先を `build/intermediate/qt-mingw1310/Testing` へ変更。cppcheck の対象に `native_file_dialog.cpp` を追加。
- 文書: 環境・配布・配布用 readme・第三者ライセンス（VC++ ランタイムの項を MinGW-w64 ランタイムの項へ）・HISTORY を更新。
- 検証: CI（Private リポジトリ）で確認する。結果は下記に追記する。

## 確認項目
- CI（MinGW）の全工程成功。
- CI が作るパッケージの検査（MinGW のランタイム 3 DLL の存在、Svg・qtiff・qgif・qico・Dialogs・qmltypes の不在）と、ファイル数・容量。

## 結果（CI: Private リポジトリ、run 35557069110、4ce681e）
- 全工程成功（Install Qt 6 and MinGW、Build test and deploy、Verify package、Static analysis を含む）。初回で通った。
- ログで確認: `The CXX compiler identification is GNU 13.1.0`（MinGW）。CTest 2/2 成功。`Skipping plugin` で qsvg・qtiff・qgif・qico が除外された。
- CI が作ったパッケージ: `Package verified: ... (123 files, 49.7 MB)`。ローカルの MinGW ビルドで同じ手順を実行した結果（123 ファイル・49.7MB）と完全に一致した。＝手元と公開物が同じ構成になった。
- Release ワークフロー（ZIP 生成・添付）はタグを打つまで未実行。`release.yml` の Qt 導入・ビルド・検査は `ci.yml` と同じ手順。
