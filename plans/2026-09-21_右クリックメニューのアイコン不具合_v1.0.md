# 右クリックメニューの小さなアイコンの不具合

## ユーザー指示（原文・2026-09-21）
- 「右クリックメニューの小さなアイコンが壊れてるかなんか変わっている」

## ユーザー指示 2（原文・2026-09-21、同じ作業の途中で追加）
- 「heic画像を右クリックしてもメニューに出てこない」
- これにより、1 件目の「右クリックメニュー」は、エクスプローラーの右クリックメニュー（設定ダイアログで登録する「QuickImageViewで開く」）を指すと確定した（アプリ内のメニューではない）。HEIC の指摘は、その登録エントリが HEIC 画像で表示されないという別の不具合として、この計画書で一緒に扱う。

## ユーザー指示 3（原文・2026-09-21、同じ作業の途中で追加）
- 「対応している種類の画像全ての右クリックメニューに出るようにして」
- 解釈: アプリが開ける画像の種類（`NativeFileDialog::openImageSuffixes()` の全拡張子。仕様の「開く」対象）のすべてで、エクスプローラーの右クリックメニューに「QuickImageViewで開く」が出るようにする。HEIC だけの対処ではなく、全拡張子を対象にする。

## 前提（未確認。これから調査する）
- ユーザーは、右クリックメニュー（画像上のコンテキストメニュー）の項目に付いている小さなアイコンの表示が、以前と違う（壊れている、または別のものになっている）と述べている。どのバージョンからか、どのアイコンかは、原文からは分からない。
- 変更の候補（推測ではなく、調査で確かめる対象）: v4.0.0 の Qt Quick 化、v4.1.0 の配布物の最小化（Svg モジュール・画像プラグインの削除。コミット f71cf18、4ce681e）。

## 調査項目
1. 右クリックメニューのアイコンの実装（QML の定義、画像の種類、読み込み方法）。
2. 配布物（dist / ZIP）に、そのアイコンの描画に必要なものが入っているか。
3. 3.x（Win32、v3.1.3）との差、および v4.0.0・v4.1.0 との差。
4. 原因の特定 → 修正 → テスト。

## 調査で確認した事実（2026-09-21）
- アプリ内の右クリックメニュー（`imageContextMenu`）の項目に、アイコンの指定は無い（QML に icon の記述なし）。ユーザーが指す「小さなアイコン」は、エクスプローラーの右クリックメニューに登録される「QuickImageViewで開く」（設定ダイアログで登録）の項目のアイコンである可能性が高い。ただし、ユーザーの画面は私からは見えず、どちらを指すかは原文から確定できない。
- この PC のレジストリ（`HKCU\Software\Classes\SystemFileAssociations\image\shell\QuickImageView`）の `Icon` は `<リポジトリ>\dist\QuickImageView.ico` を指す。**このファイルは存在しない**（`dist` に `.ico` は無い）。command は `dist\QuickImageView.exe "%1"` で、実在する。
- 原因の経緯: 登録処理（`setContextMenuRegistered`）は「exe の隣に `QuickImageView.ico` があればそれを、無ければ exe をアイコンにする」。v4.0.0 までは deploy が `.ico` を dist と ZIP に入れていたため、`.ico` のパスで登録された。v4.1.0 の最小化（4ce681e）で deploy が `.ico` をコピーしなくなり（`verify_package.ps1` も `.ico` の同梱を禁止）、deploy は毎回 dist の exe 以外を削除するので、登録済みのアイコンのパスが指す先が消えた。
- exe に埋め込まれたアイコン（`QuickImageView.rc` の `IDI_ICON1`）は無事で、16・20・24・32・48px を実際に描画して `.ico` と同じ絵であることを目視で確認した。アイコンの画像そのものは壊れていない。
- 既存のテストに、登録処理を検証するものは無い（登録状態を読むだけ）。

## 原因（結論）
登録済みのエントリの `Icon` が、v4.1.0 で消えた `QuickImageView.ico` を指したままになっている。エクスプローラーはアイコンのファイルを読めず、項目のアイコンが表示されない（または既定のものになる）。v4.0.0 以前に登録したユーザーが v4.1.0 で `.ico` を失うと同じ状態になる。

## HEIC で出ない件の調査結果（2026-09-21、実物で確認）
- 検査プログラム（`IContextMenu::QueryContextMenu` でシェルの右クリックメニューを画面なしで組み立て、項目を列挙する。読み取りのみ）で、この PC の空のサンプルファイルを調べた。同じ登録（`SystemFileAssociations\image\shell\QuickImageView`）に対し、`a.jpg`・`a.png` には verb `QuickImageView` が**ある**が、`a.heic`・`a.heif`・`a.webp` には**無い**。他の verb（open、print、Quick7Zip など）は `.heic` にも出ている。
- `HKCR\.heic` は `PerceivedType=image` なのに、`image` 全体の登録がシェルに反映されない。理由は特定していない（未解明）。この PC では、既定の ProgId が無い拡張子（.heic / .heif / .webp）で起きている。
- 一時的に `SystemFileAssociations\.heic|.heif|.webp\shell\QIVProbeVerb` を作って同じ検査をしたところ、3 拡張子とも**表示された**（検査後に削除し、削除を確認済み）。拡張子ごとの登録は、この PC で確実に反映される。
- 3.x（v3.1.3）の登録も `image` 全体だった（MSI の HEIC 関連付けがあったが、Qt 版では復元していない）。

## 修正方針
1. **拡張子ごとに登録する**: `HKCU\Software\Classes\SystemFileAssociations\.<拡張子>\shell\QuickImageView`（と `command`）を、対応する画像の全拡張子に作る。対象は、アプリが開く形式（`NativeFileDialog::openImageSuffixes()` の全て。jpg・jpeg・png・tif・tiff・bmp・gif・webp・heic・heif）に、仕様で WIC が開くとしている ico・jxr・wdp・hdp・dds を加えたもの。従来の `image` 全体のキーは、登録時に削除して置き換える。解除時は全て削除する。
2. **アイコンは exe の埋め込みアイコン**（`"<exe のパス>",0`）に固定する。別ファイルの `.ico` には依存しない。
3. **起動時の自己修復**: 登録済みのエントリが「この exe のもの」なら、拡張子ごとの登録・アイコンが揃っているかを調べ、足りない・古いものだけを書き直し、従来の `image` キーを消す。他の exe のエントリには触れない。これで、この PC の既存の登録（`image` 全体・消えた `.ico` を指す）も、新しい版を起動するだけで直る。
4. 新規モジュール `src/app/context_menu_entry.{h,cpp}` に、上記の登録・解除・判定・修復を置く。テストは実際のレジストリを使うが、専用の一時キー（`HKCU\Software\maktak-105\QuickImageViewTest\...`）で行い、ユーザーの実際のエントリには触れない。
5. 仕様（`docs/spec*.md`）と `HISTORY*.md`（未リリース）に記載する。
6. 最後に、検査プログラムで、新しい版を起動した後に `.heic`・`.heif`・`.webp` を含む全拡張子に verb が出ること、アイコン（メニュー項目のビットマップ）が付くことを実物で確認する。

## 結果（2026-09-21 実施）

### 実施した変更
- 新規 `src/app/context_menu_entry.{h,cpp}`: 拡張子ごとの登録・解除・判定・起動時の修復。アイコンは `"<exe>",0`。`suffixes()` は `openImageSuffixes()` の全て + ico・jxr・wdp・hdp・dds（15 拡張子）。
- `src/app/qt_app_controller.cpp`: 登録処理を新モジュールへ置き換え（別ファイルの `.ico` を探す処理を廃止）。
- `src/app/qt_main.cpp`: 起動時に `ContextMenuEntry::repair()`（`--convert` では実行しない）。
- `scripts/install.ps1` / `uninstall.ps1`: 同じ拡張子ごとの登録・解除にそろえた。`-RegistryRoot` 引数を追加（検証用に場所を切り替えられる）。install はアイコンファイルのコピーをやめた。
- `CMakeLists.txt`: 新モジュールを 3 つのターゲットへ追加。コントローラーのテストに `QIV_SOURCE_DIR` を追加。
- 文書: `docs/spec*.md`、`src/app/help/help*.md`、`README*.md`、`docs/distribution/readme*.txt`、`HISTORY*.md`（未リリースの節）。

### 確認結果（実物）
- **修復前の再現**（この PC）: 検査プログラムで、`.jpg` `.png` `.tif` `.gif` `.bmp` `.ico` には項目が出るが、`.heic` `.heif` `.webp` `.jxr` `.dds` には**出ない**。出ている項目のアイコンをシェルの描画結果（16×16 ビットマップ）で取り出して見ると、**空白の白い書類アイコン**だった（`.ico` ファイルが無いため）。
- **拡張子ごとの登録が効くこと**: 修正前に、一時 verb（`QIVProbeVerb`）を `.heic` `.heif` `.webp` に作って検査し、3 拡張子とも表示されることを確認（検査後に削除を確認）。
- **修正後**: 新しい exe を 1 回起動して（通常終了、終了コード 0）起動時の修復を実行。レジストリで、`image` 全体のキーが消え、`.heic` に「QuickImageViewで開く」・`Icon="…\dist\QuickImageView.exe",0`・command が入ったことを確認。検査プログラムで **15 拡張子すべてに項目が出る**こと、アイコンの描画画素数が全て 204（修復前は汎用アイコンの 189）で、絵が QuickImageView の緑の円と山であることを目視で確認した。最終ビルド後も同じ結果。
- **テスト**: コントローラー 39 件（新規 8 件: 拡張子の網羅、アイコン値、拡張子ごとの登録と旧 `image` キーの置き換え、解除、旧エントリの移行修復、他の exe の登録に触れないこと、登録が無ければ何も作らないこと、スクリプトと拡張子の一覧の一致）、QML 28 件。すべて成功。レジストリのテストは専用の一時キーで行い、テスト後に残らない。
- **スクリプト**: 一時のレジストリ領域と一時のインストール先で実際に実行し、`install.ps1`（15 拡張子、旧キーの削除、アイコンファイルなし、他者の値の保持、`-NoRegisterContextMenu`）と `uninstall.ps1`（全削除、空キーの削除、値のあるキーの保持、インストール先の削除）が全項目 OK。あなたの実際のエントリには触れていない。
- **cppcheck**: 指摘なし（C++ として、新モジュールと `qt_main.cpp`）。

### 見つけて直した自分の誤り
- 削除処理が、`.ext` や `shell` キーに他の値（既定の verb 名など）があっても消しうる実装だった。値もサブキーも無い場合だけ消すように直し、テストにした。
- 検証用のスクリプトの期待値が、パスの短い形式（8.3）のままで、初回は誤って FAIL になった（スクリプト自体は正しかった）。期待値を直して再実行し、全項目 OK。

### 未確認・制約
- **エクスプローラーの実際の画面**: 私はあなたの画面を見られない。実物確認は、シェルが組み立てるメニューのデータ（`IContextMenu::QueryContextMenu`）と、そこに含まれるアイコンのビットマップまでで、実際に右クリックして描画された見た目そのものではない。
- **Windows 11 の新しいメニュー**: サードパーティの項目は「その他のオプションを確認」（従来のメニュー）の中に出る。今回はそこ（従来のメニューのデータ）を確認した。新しいメニューの側では、この方式の項目はそもそも表示されない仕様。
- **.heic で最初に出なかった理由**: 特定していない（`HKCR\.heic` は `PerceivedType=image` なのに、`image` 全体の登録が反映されなかった）。拡張子ごとの登録で反映されることは実物で確認済みで、原因の解明は、修正の要件としていない。
- **他の PC の既存ユーザー**: 起動時の修復は、この PC の状態（旧 `image` 登録 + 消えた `.ico`）で確認した。他の状態（複数の場所に配置した exe など）は、テストの範囲で確認した。

- あなたの実際のレジストリは、上記の新しい exe の起動により、修復後の状態になっている（`image` 全体のキーは削除、15 拡張子のエントリを作成）。
