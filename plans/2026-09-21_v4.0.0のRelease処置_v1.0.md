# v4.0.0 の Release の処置（ダウンロード停止と不具合の記載）

## ユーザー指示（原文・2026-09-21）
- 「1. DLできない様に、バグで起動しないと記載する」
- 「2. 具体的に何？」
- 経緯: 直前の報告で、Public 化後に残っていること 2 点を挙げた。1 は「v4.0.0 の Release が、取り下げ済みでハングするのに、注記が無くダウンロードできる」。2 は「公開されている個人情報（古い計画書 2 件のローカルのユーザー名を含むパス、コミットの作者メール）」。これらへの回答と質問。

## 解釈
- 1: v4.0.0 の Release で、(a) 配布物（ZIP）をダウンロードできなくし、(b) Release の説明に、不具合があり使えないこと（最新版は v4.2.0）を記載する。ユーザーの「バグで起動しない」という表現は、事実と合っているかを記録で確認してから、書く内容を決める（推測で書かない）。
- 2: 公開されている個人情報が、具体的に何か（どのファイルの何行目に何が、何件のコミットに何が入っているか）を、実物で調べて、ユーザーに説明する。この計画書（公開リポジトリの文書）には、ローカルのユーザー名やメールアドレスの実際の値は書かない。説明はユーザーへの返信で行う。

## 実施内容（予定）
1. v4.0.0 の不具合の事実を、リポジトリの記録（HISTORY、`plans/`、コミットのメッセージ）で確認する。
2. 削除前に、v4.0.0 の Release の添付ファイルを、ローカルに退避する（削除は元に戻せないため）。
3. Release の説明に、取り下げの注意（日本語と英語）を、既存の本文の前に追加する。
4. ZIP を削除する。GitHub が自動で付ける「Source code」（ソースの圧縮ファイル）は、タグに付くもので、外せない。配布物（実行ファイル）ではない。
5. 認証なしで、Release のページに注意が出ること、ZIP のダウンロードができないことを確認する。
6. 個人情報の調査（コミット履歴全体を対象）を行い、ユーザーに報告する。

## 事実の確認（1: v4.0.0 の不具合。リポジトリの記録より）
- ハング: 表示倍率の異なるモニター間でウィンドウを動かすと、ハングする。修正前のビルドで、実デスクトップで再現済み（`plans/2026-09-21_ウィンドウ移動時ハング調査_結果_v1.0.md`）。HISTORY にも「取り下げ」として記載済み。
- 起動: v4.0.0 の ZIP（MSVC の Qt でビルド）には、Visual C++ ランタイムの DLL が入っていなかった。コミット f71cf18 に「Visual C++ 再頒布可能パッケージが無い PC では起動しない」とある。ただし、ランタイムの無い実機での起動テストは、していない。よって Release の注意には「PC によっては起動しません」と書き、「全ての PC で起動しない」とは書かない。
- ユーザーの表現「バグで起動しない」は、上記の 2 点を含む形で記載した。

## 結果（1: v4.0.0 の Release）
- 削除前に、Release の添付ファイル（ZIP と `SHA256SUMS.txt`）と元の説明文を、ローカルへ退避した（ZIP のハッシュは `SHA256SUMS.txt` と一致）。この時点で、ZIP は公開期間中に 3 回ダウンロードされていた。
- Release のタイトルを「v4.0.0 (取り下げ / WITHDRAWN)」に、説明文を、取り下げの注意（日本語と英語。不具合 2 点と、最新版 v4.2.0 を使うこと）に置き換えた。元のダウンロード手順の文は削除し、`Full Changelog` のリンクは残した。
- ZIP（`QuickImageViewQt-v4.0.0-win64.zip`）を削除した。`SHA256SUMS.txt` は残した。
- 認証なしで確認: Release のページは 200 で、タイトルと注意が表示される。ZIP の旧 URL は 404。最新のリリースは v4.2.0 のまま。
- 残るもの: GitHub が自動で付ける「Source code」の圧縮ファイル（タグのソース。アプリ本体ではない）。これはタグを消さない限り外せない。タグ v4.0.0 は消していない。

## 事実の確認（2: 公開されている個人情報。コミット履歴の全ブランチ・全タグが対象）
